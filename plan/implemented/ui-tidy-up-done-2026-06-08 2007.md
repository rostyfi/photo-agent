# ui-tidy-up

> **Status:** Draft  
> **Created:** 2026-06-08 19:48:03

## Overview

Remove dead UI code, consolidate duplicate helper logic, fix minor bugs, and reduce visual clutter in the Dash web UI — all without changing existing behaviour or splitting the monolithic callbacks file.

## Motivation

After several feature sprints (tag chaining, fullscreen viewer, progress bars, etc.) the UI layer has accumulated unused functions, redundant buttons, and copy-pasted boilerplate. Tidying now keeps the codebase maintainable and avoids confusing users with duplicate controls.

## Requirements

- **R1.** Remove unused `build_search_results()` (DataTable-based search results) from `src/components.py`. Search already renders via `build_photo_cards`.
- **R2.** Remove the redundant **"List all tags"** button (`btn-list-tags`) and `tag-list` output div from the **Search Photos** card in `src/layout.py`. The dedicated **Tag Cloud** card replaces this functionality.
- **R3.** Add `i` keyboard shortcut to toggle the metadata overlay in the fullscreen viewer.
- **R4.** Fix `datetime.now().year` in the footer so it is evaluated dynamically (or replaced with a static current year) rather than being captured once at module import.
- **R5.** Extract a reusable helper for the repeated "open DB → run query → close DB" pattern used across callbacks.
- **R6.** Extract shared batch-loop orchestration from `register_process_all_callback` and `register_reprocess_callback` into a single internal helper to eliminate ~150 lines of duplicated error-handling, state-writing, and duration-collection logic.

## Design / Approach

### Keep the monolith

We are **not** splitting `src/callbacks.py` into a package in this pass. The file stays intact; we only refactor internal duplication and remove dead code.

### Data flow changes

None. All user-visible behaviour remains identical:
- Search still returns photo cards.
- Tag cloud still chains and clears.
- Fullscreen still navigates with arrow keys.
- Batch processing still writes `batch_state.json` and WAL.

### Files to modify

```
src/components.py          - Remove build_search_results() and unused DataTable imports
src/layout.py              - Remove btn-list-tags and tag-list elements; fix footer year
src/callbacks.py           - Add _with_db() helper; add _run_batch_loop() helper;
                             replace inline DB open blocks; replace inline batch loops;
                             add 'i' key to clientside keyboard handler
tests/test_layout.py       - Remove assertions for deleted btn-list-tags and tag-list IDs
```

### Database changes (if any)

None.

### API changes (if any)

None.

## Implementation Steps

1. **Dead code removal**
   - Delete `build_search_results()` from `src/components.py`.
   - Remove `dash_table` import from `src/components.py` if it becomes unused (verify `build_photo_cards` doesn't need it — it shouldn't).
   - In `src/layout.py`, delete the `btn-list-tags` `dbc.Button` and the `html.Div(id="tag-list")` inside the Search Photos card.

2. **Fix footer year**
   - In `src/layout.py`, replace `datetime.now().year` with `datetime.now().year` evaluated fresh when `create_layout()` is called (already true, but verify), or just hard-code 2026 to avoid confusion. Decision: keep dynamic inside `create_layout()` but ensure it's evaluated there, not at module level — currently it *is* inside the function, so this may already be fine. Double-check.

3. **Add fullscreen metadata keyboard shortcut**
   - Extend the clientside `keydown` listener in `register_callbacks` to handle `e.key === 'i'` when the fullscreen modal is open, toggling `fullscreen-metadata-overlay` display.

4. **Extract DB helper**
   - Create `_with_db(folder, callback)` or `_db_or_none(folder) -> Optional[FeaturesDatabase]` in `src/callbacks.py`.
   - Replace all ~8 inline blocks of the form:
     ```python
     db_path = FeaturesDatabase.default_db_path(folder)
     if not db_path.exists(): ...
     db = FeaturesDatabase(db_path)
     try: ... finally: db.close()
     ```
     with calls to the helper.

5. **Extract batch-loop helper**
   - Create `_run_batch_loop(folder, paths, pc, strategy, limit, dry_run, prefix, …)` that encapsulates:
     - `write_batch_state(..., "running_all", …)`
     - `while` loop over chunks
     - `is_shutdown_requested()` check
     - `BatchCoordinator.run_paths_batch()` (reprocess) or `run_folder_batch()` (process all) — handle both by accepting a callable/callables
     - Consecutive-error counting & abort threshold
     - Duration collection
     - Final `write_batch_state(..., "done_all", …)` or `"aborted"`
     - Return final status string
   - Replace the bodies of `register_process_all_callback` and `register_reprocess_callback` with thin wrappers that call `_run_batch_loop()`.

6. **Update layout tests**
   - Remove `"btn-list-tags"` and `"tag-list"` from `expected_ids` in `tests/test_layout.py`.
   - Verify no other tests reference the removed layout IDs.

## Edge Cases & Risks

| Risk | Mitigation |
|---|---|
| Removing `build_search_results` breaks an external consumer | It's entirely unreferenced in the current codebase; grep confirms. |
| Layout test fails due to missing IDs | Update `expected_ids` in the same PR. |
| Batch-loop helper changes abort/error semantics | Keep exact same logic; pure extraction, no behaviour change. |
| `dash_table` import removal breaks something else | Check all usages in `components.py` before deleting. |
| Keyboard shortcut `i` conflicts with text input | The clientside listener already bails out when `activeElement` is an input/textarea/select. |
